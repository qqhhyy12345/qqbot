# 记忆维护规则

这份文档说明记忆库怎么长大的、什么时候会被整理、整理时哪些东西动不得。
改了 `compact_memory.py` 的默认值，记得同步改这里。

## 一、什么时候触发

只看**索引行数**（一个记忆文件对应一行索引，所以它同时就是文件数）。

| 项 | 阈值 | 为什么是这个数 |
|---|---|---|
| 索引行数 | **80 行** | 插件每轮注入索引的上限是 200 行 / 25KB。80 行是它的 40%：此时索引还完整可见，但作用域已经够大、重复足够多，整理一次收益明显；同时给「每 10 轮自动补记」留出 120 行余量，不会顶到截断线 |
| 文件数 | 80 个 | 兜底。正常情况下与索引行数一致，只有索引被手工改过才会分叉 |
| 手动 | 随时 | `--force` 忽略阈值 |

未达阈值时脚本直接退出，**不调用模型、不花钱、不改任何文件**。

## 二、整理时做什么

提示词不自己写，直接用插件 `core/consolidate.py` 里那份（与面板「整理记忆」完全同源）：

- 合并重复：同一个人、同一件事分散在多个文件的，合成一个
- 以新压旧：前后矛盾时保留较新的，删掉失效内容
- 相对日期换算成绝对日期（「明天」→ 具体日期）
- 一次性的旧事可删，有长期价值的即使没调用过也留
- **不编造**，只重组已有内容
- 拿不准的不动

## 三、保护机制（重要）

脚本在把操作落盘前逐条校验，违反了就拒绝并记进报告。

| # | 保护 | 效果 |
|---|---|---|
| 1 | 人物档案禁删 | `people/` 作用域里的 `user-<数字ID>.md` 永远不能被删除 |
| 2 | feedback 禁删 | 指导类记忆（你怎么要求它做事的）不允许被单独删掉，只能合并进其他文件 |
| 3 | 删除比例上限 | 单次最多删掉总数的 **40%**，防止一次大清洗毁掉半个库 |
| 4 | 删除必须有去处 | 本批次没有任何写入时禁止纯删除；理由里必须写明合并去向 |
| 5 | **软删除** | 删除 = 先把原文拷进 `_archive/<时间戳>/<作用域>/`，再移出索引。磁盘上永不真正消失，随时能捞回来 |
| 6 | 全量备份 | 任何写入前，整棵记忆树快照到 `_backup/<时间戳>/`（只备一次，跳过 `_backup` 和 `_archive` 自身） |
| 7 | 并发检测 | 提示词生成后文件又被改过（你正在聊天、机器人也在写），该文件本轮跳过 |
| 8 | 默认预演 | 不加 `--apply` 只出方案，一个字节都不改 |
| 9 | 报告留档 | 每次运行写 `reports/compact-<时间戳>.json`，记录了每个操作的理由和被拒原因 |

## 四、怎么跑

| 场景 | 做法 |
|---|---|
| **每周例行（推荐）** | 双击 `weekly-maintenance.bat`：先脱敏提升 people，再整合记忆 |
| 看方案（安全） | 双击 `compact-预览.bat` |
| 真执行 | 双击 `compact-执行.bat` |
| 只看 people 脱敏草稿 | `promote_people.py`（不加 --apply） |
| 强制整理（无视阈值） | 加 `--force` |
| 只处理某个作用域 | `--scope session` / `people` / `global` |
| 复核上次方案 | `--ops-file reports/xxx.json`（把 `results` 改写成操作数组） |

## 五、people 脱敏提升（每周）

`people` 是**对外档案**：两个说话方式共享的那一层。它只能放「换个场合也成立、又不暴露私生活」的事实，
否则要么让助手像个陌生人（你说过的事还得重讲），要么把私事漏给外人。

### 三档规则

| 档 | 内容 | 处理 |
|---|---|---|
| 绿 | 称呼、职业专业、技能、语言习惯、沟通偏好、明确说过的相处要求 | 原样写 |
| 黄 | 家乡（只到省）、正在忙的事（只写「有压力的事在推进」） | 抽象后写 |
| 红 | 具体事件、情绪细节、照片、家人、经济、健康、情感、精确地点、真名、互动过程 | 一律不写 |

### 每周流程

1. 跑 `weekly-maintenance.bat`
2. 第一步 `promote_people.py --apply`：读私聊里的 `user-<ID>.md` 与 `feedback-*.md`，生成脱敏版 people 档案
3. 第二步 `compact_memory.py --apply`：达阈值才整合（见第一节）
4. 报告落在 `reports/promote-<时间戳>.json` 与 `reports/compact-<时间戳>.json`

### 校验（写入前的硬拦截）

- 红档词命中 → 拒绝写入（**只扫描「别碰的」段落之外**，那一段本来就在列举禁止项）
- 缺固定边界句、缺分段标题、长度越界 → 拒绝
- description 为空或超过 60 字 → 拒绝

### 为什么不让它自己写

模型自己写 people 时会顺手把过程也写进去（谁拒绝了谁、他先提了什么），
这些在别的场合被说出来就是事故。所以统一走「模型出草稿 + 规则校验 + 人工复核」。

## 六、出问题了怎么办

1. **整库回滚**：把 `_backup/<时间戳>/` 里的内容拷回 `bot-memory/`（覆盖）。
2. **捞回单个被删文件**：`_archive/<时间戳>/<作用域>/` 里有原文。
3. **看某次为什么这么改**：`reports/compact-<时间戳>.json`，每个操作带 `reason`。
4. **彻底停用**：脚本不在任何启动项里，不双击就不会跑。

## 七、已知边界

- 只在**默认定时/手动**运行时整理，不挂计划任务（按你的要求，调度暂不启用）
- `enable_forgetting` 保持关闭：旧记忆不会自动淡出，只靠整理合并
- 模型合并得是否得体，取决于输入质量；文件少时它常常「认为无需整理」，这是正常的
- 插件升级若改了 `core/` 的接口，脚本会 ImportError 或解析失败并**放弃本轮**，不会乱写
